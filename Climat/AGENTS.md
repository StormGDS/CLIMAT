# Работа с Climat

Требования текущего пользователя имеют приоритет. Актуальные источники:
SPEC.md, PHONE_PROTOCOL_V3.md, STAGE4_FLASH.md, PROTOCOL.md. Исторические отчёты
и docs/history не возвращают удалённые требования. HTML — только демонстрация.

- Нет target и прогнозного управления. Каждый канал задаётся Ton/H. K2 имеет
  положительную скорость остывания; досрочное включение только при actual logical K1.
  Выше Ton2 при замедлении снять ранний запрос; после достижения Ton2 держать
  температурную защёлку до Ton2+H2. Нет фильтра, окно производной 5 с.
- AUTO: MIN_ON двух групп 1..600 с, MIN_OFF фиксирован 30/60 с; K2 не работает без K1. При завершении ON K2
  удерживать K1 до выключения K2. MANUAL — независимая наладка каналов без минимумов,
  с авариями и взаимной блокировкой. Авария: K1/K2 OFF,K3 ON,K4 OFF немедленно.
- ROM S1/S2 задаются явно, уникальны, CRC8/family проверяются. Сохраняются по SAVE.
  Поиск не подменяет роли. Смена привязок очищает старые измерения и переводит в AUTO.
- Новые Flash v5 (72 Б) и протокол v3. Сохранять совместимость чтения валидных
  Flash v1-v4; не писать при миграции до SAVE. Протокол v1/v2 отклонять через VERSION.
  При новых изменениях обновлять документацию, codec, vectors и тесты.
- Не придумывать заводские S, FAIL_COUNT/RECOVER_COUNT: 0 означает не настроено.
- Общий C core без HAL/CMSIS/номеров GPIO. Без malloc/free, float и RTOS.
  F030 <=15360 Б Flash и <=4096 Б RAM со стеком 2048 Б. CONFIG одна страница
  0x08003C00..0x08003FFF, без копии/журнала; риск утраты при SAVE уже принят.
- F767 CONFIG 0x08010000..0x0801FFFF, код первые64К; не менять option bytes.
  F767 физические реле разрешены active HIGH, OFF перед ON; F030: approved PA1..PA4, active HIGH, OFF before ON (2026-11-02).
  F030 pin map approved 2026-11-02. Never flash F030 image to F767.
- BT05/v6.1 peripheral, телефон central, FFE0/FFE1. Ограниченный стартовый AT-профиль,
  неизвестным модулям setters не посылать, PIN/baud/security/factory reset не менять.
  Имя CLM-XXXXXX применять после SAVE/reset, уникальность не гарантировать автоматически.
- После общих изменений собирать F767 (python build.py) и F030
  (targets/stm32f030f4/build.ps1), запускать tests/run_tests.py обычный и --compact.
  Зависимости тестов unicorn/pyelftools; это исполнение C в эмуляторе, не аппаратные тесты.
  Не объявлять сборку, испытания платы, Flash, BLE или контактов успешными без выполнения.

Обновление 31.10.2026: R/Hrate и MIN_ON двух групп передаются через v3 SET_CONFIG.
Точные поля/границы — PHONE_PROTOCOL_V3.md, android_config_manifest_v3.json.
R=Hrate=0 и MIN_ON=30/60 — совместимые значения миграции. Запрет роста перекрывает
температурную защёлку K2, выключение ждёт MIN_ON и зависит от текущего запрета.
CONFIG GET показывает новые значения; старый AUTO SET сохраняет R/Hrate.
Android и HTML в этой задаче не изменялись. Отчёт: TEST_REPORT_2026-10-31.md.

Ветка dev/f030-no-service-console: F030 собирается с CLIMAT_NO_SERVICE_CONSOLE; PA5 не используется. USART1 только BLE 9600 8N1. Не возвращать текстовую консоль в F030. F767 сохраняет стендовую консоль. Проверять tests/run_tests.py --no-console --compact дополнительно.
