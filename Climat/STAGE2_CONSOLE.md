# Этап 2 — консоль и логический арбитр

Реализовано и испытано на NUCLEO-F767ZI 26.10.2026. Пользователь подтвердил отсутствие реле/нагрузок. Физическое управление намеренно заблокировано: команды меняют только логическую модель, не GPIO. Это не готовое автономное регулирование температуры.

## Консоль

COM3 / STLink Virtual COM Port, 115200 8N1, без flow control. Команды в верхнем регистре, завершаются CR или LF. CRLF также принимается. Для удобства сначала `STREAM OFF`, затем `HELP`. `STREAM ON` возвращает секундную телеметрию. COM3 освобождён после проверки.

| Команда | Действие |
|---|---|
| HELP | Список реализованных команд |
| STATUS / RELAYS | Режим, источник, авария, requested/logical маски, блокировка физических выходов, остаток MANUAL |
| SENSORS | Немедленный вывод последнего результата; не запускает внеочередную конверсию |
| STREAM ON / OFF | Включение/выключение периодического вывода; опрос продолжается |
| MODE AUTO / MANUAL | Переключение режима, очистка ручного запроса |
| RELAY 1..4 ON / OFF | Запрос к модели, только MANUAL без аварии и конфликта нагрев/охлаждение |
| CONFIG GET | Поддерживаемые параметры RAM |
| CONFIG SET FAIL_COUNT 1..255 | Число ошибок S1 до переключения на исправный S2 |
| CONFIG SET RECOVER_COUNT 1..255 | Число успешных чтений S1 до возврата с S2 |
| CONFIG SET MANUAL_TIMEOUT 1..3600 | Тайм-аут MANUAL в секундах, заводское значение 600 |
| SELFTEST | Изолированные тесты моделей на MCU, без изменения рабочих параметров и GPIO |
| SAVE / LOAD / DEFAULT | Явная ошибка NOT_IMPLEMENTED; Flash не записывается |

FAIL_COUNT и RECOVER_COUNT при старте равны 0 — признак «не настроено», не допустимое пользовательское значение. До задания обоих параметров резервирование не активируется. Числа 3/5 использовались только в тесте, не назначены defaults. После завершения теста плата сброшена: AUTO, MANUAL_TIMEOUT=600, резервирование UNCONFIGURED, телеметрия включена.

Биты маски: bit0 K1, bit1 K2, bit2 K3, bit3 K4. Например `logical=0x4` означает только K3. `requested` — запрос, `logical` — результат арбитра после ограничений. `physical=LOCKED` означает, что ни одна маска не выдана на пины. Успешный ответ на RELAY означает принятие запроса, а не включение реле: результат может ждать MIN_ON/OFF. `source=S0` означает отсутствие пригодного выбранного источника.

## Реализованные правила модели

- AUTO при каждом reset. Пороговый/прогнозный регулятор AUTO ещё не определён, поэтому его рабочий запрос равен нулю, статус auto=UNCONFIGURED.
- При первом запуске до окончания первого опроса все логические выходы выключены; ручные команды запрещены. Отсутствие начальных измерений не выдаётся за подтверждённый отказ обоих датчиков.
- При недостоверности обоих — немедленно K1/K2 OFF, K3 ON, K4 OFF, выше MANUAL и любых временных ограничений. Ручной запрос очищается и после восстановления сам не возобновляется.
- Потеря обновлений более чем на 2500 мс также вызывает эту маску. 2500 мс — новый инженерный параметр стенда, а не ранее утверждённый пользовательский порог.
- Минимальные ON и OFF: 30 с для K1/K2, 60 с для K3/K4. Первый ON также ждёт минимальный OFF от старта. После выхода из аварии K3 может оставаться логически включённым до выполнения минимального ON; нагрев в это время блокируется.
- Нагрев и охлаждение не включаются вместе. Противоречивый ручной запрос отклоняется. Сначала выполняются разрешённые OFF, затем ON с проверкой действующих выходов противоположной группы.
- Успешные `MODE MANUAL` и `RELAY` обновляют таймер бездействия. STATUS/SENSORS/STREAM/CONFIG/SELFTEST его не продлевают. По тайм-ауту AUTO и очистка запроса; минимальное ON остаётся применимым. Такой выбор команд продления явно определён для этого этапа.
- S1/S2 пока — адреса из порядка поиска, запомненные до reset. Перед эксплуатацией требуется постоянная ROM-привязка физических основного/резервного датчиков. Производные в SENSORS относятся к отдельным датчикам; применение прогноза выбранного источника к AUTO ещё не реализовано.

Приём UART: IRQ, статическая очередь 128 байт, строка до 95 символов. Слишком длинная строка отбрасывается до конца, не исполняется обрезанный префикс. При потере RX/переполнении очереди — ошибка и повторная синхронизация по новой строке; отправить пустую строку и повторить команду. Reset-low 1-Wire выполняется с разрешёнными IRQ; критический участок определения presence — 70 мкс. Реальные электрические тайминги логическим анализатором не измерены.

## Проверки

Прошивка Release собрана, записана через ST-LINK и верифицирована. SELFTEST на самой плате: **PASS failures=0x0**. Проверены в изолированных моделях: старт, границы MIN_OFF/MIN_ON, взаимная блокировка, аварийное отключение нагрева и K3 ON, запрет ручной отмены аварии, очистка запроса после аварии, тайм-аут, переключение/возврат датчиков, устаревшие данные, переполнение счётчика времени, CRC и отрицательная температура.

Через настоящий COM3 проверены HELP/STATUS/SENSORS, STREAM, CONFIG GET/SET, отклонение нулевого порога, запрет RELAY в AUTO, принятие запроса в MANUAL, отклонение противоположной группы, возврат AUTO при тестовом тайм-ауте 1 с, явный отказ SAVE, отбрасывание строки 110 символов и восстановление приёма. После reset подтверждены AUTO и сброс тестовых настроек RAM. По SWD после команд: GPIOF ODR=0x8000 (только DQ отпущена), GPIOE ODR=0 — физические реле не переключены.

Единственный подключённый DS18B20 ROM=28B221F545240B6C продолжает показывать около 25,06…25,13 °C, errors=0. Реальное резервирование двух датчиков ещё не испытано; его тест выполнен на модели, не на двух физических датчиках.

control_core, service_console и control_selftest дополнительно компилируются для Cortex-M0 с -Os -Wall -Wextra -Werror, без HAL-зависимостей. Release F767: text=19008, data=124, bss=2172; BIN=19140 байт. Стенд с HAL, диагностическими строками и встроенными тестами **превышает 15 КиБ Flash**; лимит конечного F030 не выполнен и не отменён. Требуются отдельный LL-порт, перенос тестов из production и проверка полной целевой сборки и максимального стека.
