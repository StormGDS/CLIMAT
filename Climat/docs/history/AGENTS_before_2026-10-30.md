# Работа с Climat

Основные источники: SPEC.md, PROTOCOL.md, исходный thermostat_android_all_screens.html. Требования текущего пользователя имеют приоритет. HTML — демонстрационный дизайн, его числа и поведение не отменяют SPEC.

Меняйте существующий climat_test.ioc, не создавайте конкурирующий основной проект. Сохраняйте общий C core для F767 и F030 без HAL/CMSIS; LL/регистры остаются в адаптерах. Целевая F030 сборка <= 15360 байт Flash и <= 4096 байт RAM со стеком, без malloc. Flash настроек — одна страница, без резервной копии; принятый риск потери при SAVE не заменять двухстраничным журналом.

При отказе обоих датчиков K1/K2 OFF, K3 ON, K4 OFF, выше MANUAL и временных ограничений. 28.10.2026 пользователь подтвердил: реле/нагрузки NUCLEO подключены, активный уровень HIGH, физическое управление разрешено. F767 применяет только итоговую маску арбитра; сначала OFF на обоих портах, затем ON. F030 пока LOCKED до согласования его платы. Не выдумывайте байтовый протокол, defaults и формулы, помеченные как открытые. Не объявляйте генерацию, сборку или аппаратные тесты успешными без выполнения.

Последнее уточнение пользователя 28.10.2026: в MANUAL не применяются ни MIN_ON, ни MIN_OFF — ON, OFF и повторное ON исполняются сразу. AUTO сохраняет оба минимума. Взаимная блокировка нагрева/охлаждения и аварийная маска K3 имеют прежний приоритет над ручными командами. Не возвращать старые задержки MANUAL по историческим разделам SPEC/STAGE2 и предыдущему этапу исправления OFF.

С этапа 4 сохраняйте резерв CONFIG 0x08010000–0x0801FFFF в обоих F767 linker scripts: код только в первых 64K, без загрузочной секции CONFIG. Запись — сектор 2 single-bank / 4 dual-bank; option bytes не менять. Формат хранения v1 и его ограниченный состав описаны в STAGE4_FLASH.md. Это не адрес настроек F030 и не сетевой протокол. Новые поля требуют изменения версии и тестов валидации.

После полевых испытаний действует окно производной 5 с и формат v2; чтение валидной v1 переносит остальные уставки без сброса. Горизонт прогноза остаётся 30 с. Общие константы — thermal_timing.h; обновление Flash только по SAVE.

По запросу реализации обмена с телефона определён новый контракт PHONE_PROTOCOL_V1.md (COBS, CRC16, sequence, стоп-и-жди). Он заменяет прежний открытый пункт о байтовом формате. Сохраняйте общий backend настроек/арбитра и эталонные tests/phone_vectors.json; текст USART3 не направлять в USART6. UUID BLE не назначать без проверки модуля.

Формат Flash v3 хранит имя device_name[3] в прежних reserved offsets 29,42,43; размер записи остаётся 48. v1/v2 мигрируют с пустым именем. GET/SET_CONFIG не меняют длину, имя доступно отдельными opcode 0x0C/0x0D. Не назначайте имена автоматически как гарантированно уникальные; advertising name модуля — отдельная настройка.

Пользователь уточнил роль: телефон central, модуль peripheral/slave. Автопрофиль при запуске — только проверенный BT05/v6.1; ROLE=0, имя CLM- + 6 HEX-цифр device_name, UUID/CHAR FFE0/FFE1 (считаны на модуле). bt_boot.c должен оставаться ограниченным по времени и не блокировать AUTO; неизвестная прошивка не получает setters. Применение Bluetooth-имени после SAVE и перезапуска MCU разрешено пользователем; не менять PIN/baud/security и не выполнять factory reset.

Сборка F030 — targets/stm32f030f4/build.ps1, результат OPTIMIZATION_F030.md. Сохраняйте строгие linker ASSERT 15 КБ Flash, 4 КБ RAM, стек 2048 Б и страницу CONFIG 0x08003C00..0x08003FFF без загрузочной секции. После общих изменений проверяйте F030 и F767. CLIMAT_PRODUCTION исключает только стендовые тесты; бинарный контракт сохраняется. Текущая F030 pin map предварительная, аппаратно не подтверждена; не объявлять её согласованной и не прошивать F030-образ в F767. После изменения horizon пересмотреть целочисленное масштабирование: сейчас compile-time assert требует 30 с.
