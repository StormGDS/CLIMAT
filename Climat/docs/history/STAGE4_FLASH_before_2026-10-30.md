# Этап 4 — редактирование и хранение параметров

Реализовано и испытано на NUCLEO-F767ZI 27.10.2026. При запуске параметры читаются из Flash **до первого решения AUTO**. При пустой или недостоверной записи применяется принятый пользователем тестовый профиль; консоль сообщает причину. Сам запуск ничего не записывает во Flash. Режим после любого запуска — AUTO, состояния реле и MANUAL не сохраняются. Физические выходы по-прежнему заблокированы.

## Работа с консолью

COM3, 115200 8N1. Команды завершаются Enter. Для удобства редактирования: `STREAM OFF`; после работы: `STREAM ON`. Опрос датчика продолжается независимо от вывода.

| Команда | Результат |
|---|---|
| `AUTO GET` | Текущие уставки и чередование вентиляторов |
| `AUTO SET target h1on h1off h2on h2off c1on c1off c2on c2off` | Проверка и применение всего набора уставок в RAM, единицы 1/16 °C |
| `AUTO ALTERNATE ON` / `OFF` | Изменение чередования в RAM |
| `CONFIG GET` | Пороги резервирования и тайм-аут MANUAL |
| `CONFIG SET FAIL_COUNT 1..255` | Число ошибок до перехода на резервный датчик |
| `CONFIG SET RECOVER_COUNT 1..255` | Число успешных чтений до возврата на основной |
| `CONFIG SET MANUAL_TIMEOUT 1..3600` | Тайм-аут MANUAL, секунды |
| `CONFIG STORAGE` | Состояние записи и совпадение с RAM: `flash=VALID/EMPTY/INVALID/IO_ERROR`, `ram_matches=0/1` |
| `SAVE` | Сохранение текущих параметров и проверка чтением; `OK SAVE VERIFIED` |
| `LOAD` | Возврат сохранённых параметров в RAM; переход в AUTO |
| `DEFAULT` | Принятый тестовый профиль в RAM; переход в AUTO. Для сохранения нужен отдельный SAVE |

Если данные не менялись, `SAVE` отвечает `OK SAVE UNCHANGED` без стирания. Ошибка LOAD сохраняет текущие параметры RAM; ошибка SAVE также не заменяет RAM. После `BUSY SAVE` дождитесь `OK` или `ERR`, прежде чем отправлять следующую команду: при стирании приём UART временно приостановлен, накопленные команды отбрасываются. Изменённые через консоль параметры без SAVE пропадают при перезапуске.

Пример установки принятого профиля и сохранения:

```
STREAM OFF
AUTO SET 184 176 184 168 176 400 384 560 544
AUTO ALTERNATE OFF
CONFIG SET MANUAL_TIMEOUT 600
SAVE
CONFIG STORAGE
STREAM ON
```

Нормальный результат — `OK SAVE VERIFIED` (или UNCHANGED), затем `flash=VALID ram_matches=1`. При следующем старте — `SETTINGS BOOT source=FLASH reason=VALID`.

Тестовый профиль: K1 по прогнозу ≤11 / ≥11,5 °C, K2 ≤10,5 / ≥11 °C; при измеренной температуре ≤10,5 °C запрашиваются оба нагревателя. Вентиляторы включаются >25 / >35 °C, выключаются ≤24 / ≤34 °C. Чередование выключено, MANUAL_TIMEOUT=600. FAIL_COUNT и RECOVER_COUNT в профиле равны 0 («не настроено»); утверждённых заводских значений для них нет. Для включения резервирования нужно задать оба параметра и выполнить SAVE.

## Организация Flash

Для прототипа F767 запись находится по **0x08010000**. Сектор зависит от nDBANK: single-bank — сектор 2, 32 КиБ; dual-bank — сектор 4, 64 КиБ. Эти адреса подтверждены [официальным примером STM32CubeF7](https://github.com/STMicroelectronics/STM32CubeF7/blob/master/Projects/STM32F769I-Discovery/Examples/FLASH/FLASH_EraseProgram/Inc/main.h) и организацией памяти [RM0410](https://www.st.com/resource/en/reference_manual/dm00224583-stm32f76xxx-and-stm32f77xxx-advanced-arm-based-32-bit-mcus-stmicroelectronics.pdf).

В обоих linker scripts программа ограничена первыми 64 КиБ, а CONFIG резервирует 0x08010000–0x0801FFFF. Загрузочной секции CONFIG нет, поэтому обычная адресная загрузка ELF не стирает настройки. Полное стирание MCU их удалит. До первой записи все 64 КиБ были прочитаны и проверены как пустые (0xFF). На подключённой плате подтверждён single-bank; dual-bank учитывается кодом, но на этой плате не испытывался. При перестановке банков адаптер отказывает в доступе; option bytes не меняются.

Стирается **один** сектор, без резервной копии и журнала. Сначала программируются payload и CRC, затем magic как последний маркер завершения, после чего выполняется проверка чтением. Прерывание питания во время SAVE может уничтожить настройки — ранее принятый компромисс сохранён. После такого сбоя используется тестовый профиль, а не частично прочитанные поля. Watchdog обслуживается перед/после операции; пропущенные при остановке исполнения из Flash тики восстанавливаются по DWT. Перед проверочным чтением инвалидируется соответствующий диапазон D-cache.

Для конечного F030 остаётся выделенная страница **0x08003C00–0x08003FFF**, программа — 15 КиБ. Сериализация и валидатор общие, адреса и HAL находятся только в F767-адаптере. Отдельный адаптер записи и полная сборка F030 в этом этапе не создавались.

## Формат v3, 48 байт

Локальный формат хранения, не бинарный протокол HM-10. Все многобайтовые числа little-endian; нет зависимости от padding C-структур. v2 сократила окно до 5 с; v3 использует три прежних reserved-байта для имени устройства. Корректные v1/v2 читаются с сохранением параметров и пустым именем 000000; SAVE записывает v3. Неизвестные версии отклоняются. До SAVE при чтении старого формата CONFIG STORAGE показывает ram_matches=0.

| Смещение | Размер | Содержимое |
|---:|---:|---|
| 0 | 4 | ASCII `CLMT`, записывается последним |
| 4 | 2 | version=3 |
| 6 | 2 | length=48 |
| 8 | 18 | Девять int16 уставок в порядке AUTO SET, 1/16 °C |
| 26 | 1 | FAIL_COUNT |
| 27 | 1 | RECOVER_COUNT |
| 28 | 1 | alternate, 0 или 1 |
| 29 | 1 | device_name[0] (в v1/v2 reserved=0) |
| 30 | 2 | MANUAL_TIMEOUT, секунды |
| 32 | 2 | Фиксированный нижний предел 168 = 10,5 °C |
| 34 | 2 | Фиксированное окно производной 5 с (в прежней v1 — 30 с) |
| 36 | 2 | Фиксированный горизонт прогноза 30 с |
| 38 | 2 | Фиксированный минимум ON/OFF нагревателей 30 с |
| 40 | 2 | Фиксированный минимум ON/OFF вентиляторов 60 с |
| 42 | 1 | device_name[1] (в v1/v2 reserved=0) |
| 43 | 1 | device_name[2] (в v1/v2 reserved=0) |
| 44 | 4 | CRC32 байтов 0–43 |

CRC-32/ISO-HDLC: polynomial=0x04C11DB7 (reflected 0xEDB88320), init=0xFFFFFFFF, refin/refout=true, xorout=0xFFFFFFFF. Контроль `123456789` = 0xCBF43926. Фиксированные поля проверяются на поддерживаемые значения, но ещё не редактируются. ROM-привязки датчиков пока отсутствуют в рабочей модели и не выдуманы в этой записи. При появлении новых настроек формат должен получить новую версию. Состояния реле, текущие измерения, история прогноза и режим MANUAL не входят в запись.

Имя редактируется командами `CONFIG SET DEVICE_NAME A01` (ровно три печатных ASCII-символа без пробелов) либо `CONFIG SET DEVICE_NAME_HEX 413031` (любые три байта). CONFIG GET показывает HEX и текст; SAVE сохраняет, LOAD восстанавливает, DEFAULT очищает в RAM. Терминатор строки не хранится. Произвольное тестовое имя не назначено устройству как уникальное: исходное значение 000000 оставлено до выбора пользователем. По последующему запросу автоконфигурации при старте MCU имя используется для Bluetooth CLM-XXXXXX; см. BLUETOOTH_BOOT.md.

Версия с именем испытана на плате: чтение прежней v2, перенос всех старых полей, сохранение A01 после reset, отбрасывание неверной длины/HEX, GET/SET_DEVICE_NAME, байты 00 FF 80, сохранение имени при SET_CONFIG. Побайтовая проверка после возврата исходного имени показала сохранность остальных полей. SELFTEST и новые тесты миграции/имени — PASS; новые HELLO и GET_DEVICE_NAME побайтово совпали с JSON-векторами. Финально Flash v3, имя 000000, ram_matches=1, AUTO, PHONE TEST OFF, STREAM ON, COM3 освобождён. Новые логи и прошивка — device-name-release; прежние результаты ниже относятся к этапу 4 до добавления имени.

## Выполненные проверки

- Release собран без ошибок/предупреждений; settings, settings_selftest и service_console также скомпилированы для Cortex-M0 с `-Wall -Wextra -Werror`.
- На MCU прошли SELFTEST, AUTO_SELFTEST и SETTINGS_SELFTEST. Модель проверяет CRC, порчу каждого из 384 бит записи, пустой сектор, отсутствие последнего маркера, неизвестную версию, неверные диапазоны с корректным CRC, сохранение RAM при отказе, повторный SAVE без стирания и ошибки backend.
- На реальной Flash проверены SAVE/LOAD, сохранение всех редактируемых полей, сброс из MANUAL в AUTO, потеря несохранённых изменений, сохранность настроек при повторной загрузке ELF, DEFAULT без изменения Flash.
- В сектор записан тестовый экземпляр с испорченным CRC: при перезапуске получено `source=DEFAULT reason=INVALID`, LOAD отклонён. Затем корректная запись восстановлена и повторный старт подтвердил `source=FLASH reason=VALID`.
- Финальное состояние: во Flash принят исходный тестовый профиль, `ram_matches=1`, AUTO, STREAM ON, COM3 освобождён. S1 около 24,6 °C, ошибок 0; S2 отсутствует. GPIOF ODR=0x8000, GPIOE ODR=0: четыре релейных выхода LOW.

Release: text=26876, data=124, bss=2308 байт; BIN=27008 байт. Диагностическая F767-сборка по-прежнему превышает лимит Flash F030; фактическая максимальная глубина стека конечной прошивки ещё не проверена. Полное пропадание питания во время реального SAVE не имитировалось; его промежуточные состояния проверены моделью, отказ CRC — на плате. Логи и ELF/BIN/MAP находятся в `stage4-release` рядом с копией описания.
