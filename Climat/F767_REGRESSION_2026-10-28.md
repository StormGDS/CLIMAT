# Регрессия F767 после оптимизации, 28.10.2026

**Результат: PASS.** Актуальная Release-прошивка F767 загружена в NUCLEO-F767ZI, проверена программатором и испытана через COM3. Исходные параметры Flash восстановлены побайтово. Плата оставлена в AUTO, поток измерений включён, порт освобождён.

## Прошивка и стенд

- Плата: NUCLEO-F767ZI, ST-LINK `0672FF485550755187184831`, Device ID `0x451`, Cortex-M7, питание по ST-LINK 3,24 В.
- Release `climat_test.elf`: сборка CubeIDE/GCC, 0 ошибок и 0 предупреждений компиляции. `text=39164`, `data=124`, `bss=3548` байт; BIN с выравниванием — **39 296 байт**. Это диагностический стенд F767; размер компактного F030 остаётся отдельным результатом.
- Загрузка через SWD under-reset, проверка `Download verified successfully`, затем аппаратный reset. Образ F030 не использовался.
- ELF SHA256: `81F49CBCF31732109FF1F2B42DF4AE137CA6135B51438F58C1471D64C12E1D88`.
- BIN SHA256: `9073AEC7C44A2ABAD4A4CEE5C446017170886B1E970C714293BD694EED5E4284`.
- Один подключённый DS18B20: S1 ROM `28B221F545240B6C`. S2 не назначен/не подключён. Bluetooth на USART6, 9600 бод; консоль USART3 VCP, 115200 бод.

## Встроенные C-тесты на MCU

Все семь наборов выполнены дважды в ходе независимых прогонов. Каждый вернул `PASS failures=0x0`:

| Набор | Что проверено |
|---|---|
| SELFTEST | Арбитр, AUTO/MANUAL, минимальные времена, взаимная блокировка, тайм-аут, авария обоих датчиков, выбор источника, устаревание измерений, переполнение времени; декодирование DS18B20 |
| AUTO_SELFTEST | Гистерезис и ступени, чередование вентиляторов, прогрев производной после смены источника, нижний предел, отсутствие одновременного запроса нагрева/охлаждения; новый прогноз против прежнего 64-битного выражения на 37 453 сочетаниях |
| SETTINGS_SELFTEST | Кодирование/валидация, CRC, миграция форматов, имя v3, неизменившаяся запись, ошибки чтения/записи на изолированном RAM backend |
| TREND_SELFTEST | Окно 5 с, положительный/отрицательный наклон, сброс истории, переполнение времени, длинный разрыв; 19 513 сравнений новой производной с 64-битным эталоном |
| PHONE_SELFTEST | COBS/CRC/фреймер, повреждённый ввод, кэш повторов и конфликты sequence |
| BT_BOOT_SELFTEST | Машина состояний настройки модуля, тайм-ауты, неподдерживаемая прошивка, повторный старт и ранний бинарный обмен |
| FORMAT_SELFTEST | Компактный форматтер против libc: 679 сравнений, INT32_MIN/MAX, unsigned/hex, ширина/нули, строки, усечение, буферы ёмкостью 0 и 1, защитные байты |

Проверки аварий и крайних температур здесь используют локальные синтетические состояния C-тестов. Подключённый физический датчик не отключался и не нагревался до порогов.

## Интеграция консоли, протокола и Flash

Независимый PowerShell-клиент отправлял кадры по тестовому транспорту USART3 (`PHONE HEX`) в тот же парсер и backend MCU, которые обслуживают USART6. Проверены все opcode `0x01..0x0D`:

- HELLO, STATUS, SENSORS, GET/SET_CONFIG, SAVE/LOAD/DEFAULT, MODE/RELAY, STORAGE, GET/SET_DEVICE_NAME.
- Окно 5 с / прогноз 30 с, длины ответов, признаки блокировки физических выходов.
- Разрешённые и отклонённые команды MANUAL/RELAY, взаимная блокировка, неправильный режим, неизвестный opcode, неправильный payload, небезопасные уставки.
- Атомарность SET_CONFIG: отказ не меняет RAM; изменение тайм-аута на тестовое значение применяется; SAVE/DEFAULT/LOAD возвращают сохранённое значение; исходный профиль восстановлен.
- Повтор одинакового SAVE с тем же sequence возвращает идентичный ответ; другой запрос с занятым sequence отклоняется. Неверная версия получает ошибку; плохой CRC и фрагмент с паузой >500 мс отбрасываются без изменения режима.
- Имя из трёх байтов читается полностью; неверная длина SET отклоняется; тестовое имя `A5005A` с нулевым байтом проходит COBS и чтение; SET_CONFIG сохраняет отдельное имя; LOAD возвращает исходное `000001`. Тестовое имя не сохранялось и не применялось к Bluetooth.
- Новый ограниченный разбор десятичных чисел принимает явный `+` для прежних уставок; слишком большое число отклоняется с сохранением предыдущей конфигурации.

## Перезапуски, Bluetooth и реальный датчик

После повторных аппаратных reset:

```text
SETTINGS BOOT source=FLASH reason=VALID
BT BOOT state=READY present_by_at=1 writes=0 desired_name=CLM-000001
STORAGE flash=VALID ram_matches=1
```

Запросы к реальному модулю подтвердили `NAME=CLM-000001`, `ROLE=0`, `UUID=FFE0`, `CHAR=FFE1`; UART errors=`0x0`. Повторный запуск не выполнял setters. Полный обмен с Android по радиоканалу этим тестом не проверялся.

Наблюдение после reset подтвердило переход от WARMUP к вычислению производной примерно через 5 с истории и расчёт прогноза +30 с. У S1 ошибок измерения 0. В финальном снимке:

```text
S1 ROM=28B221F545240B6C T=21.0625 C status=OK errors=0 dT=0.000 C/min T+30s=21.062 C
S2 ROM=UNASSIGNED T=NA C status=NOT_FOUND
STATUS mode=AUTO source=S1 fault=0 requested=0x0 logical=0x0 physical=LOCKED
```

В проверенных интервалах наблюдения неожиданных перезапусков не было. Счётчик NOT_FOUND у S2 ожидаемо растёт для отсутствующего датчика. Длительный прогон и испытание нагрузок сюда не входят.

## Сохранность исходных параметров

Перед прошивкой прочитана запись 48 байт по `0x08010000`, после тестов прочитана повторно. Байты **полностью совпали**, SHA256 обеих копий:

`B8DCD0A6AAAF1448961A4E87C8956C67948E6CA462F366DA76A9DD2874B14F74`.

Финальные параметры: AUTO raw16 `184,176,184,168,176,400,384,560,544`, MANUAL_TIMEOUT=600 с, FAIL_COUNT=0, RECOVER_COUNT=0, чередование=0, имя `000001`. Это исходный профиль стенда; новые значения не назначались. Итог: AUTO, S1, fault=0, logical=0, physical=LOCKED, STREAM ON; COM3 закрыт тестовыми программами и доступен пользователю.

Код прошивки в ходе регрессии менять не потребовалось. Аппаратная проверка F030 по-прежнему отдельно: эти результаты подтверждают общую логику на F767, но не периферию, стек и тайминги F030.
