# Автоматическая настройка Bluetooth при старте MCU

Пользователь уточнил: **телефон подключается к модулю**, поэтому модуль работает как peripheral/slave, а телефон — central. MCU при каждом запуске проверяет модуль и настраивает поддержанный профиль. Отсутствие Bluetooth не останавливает терморегулятор.

## Проверенный модуль и профиль

Установленный модуль ответил `+VERSION=v6.1`, исходное имя `BT05`. Его собственный `AT+HELP` подтвердил диалект команд AT+ROLE/NAME/UUID/CHAR. Ответы и порядок параметров соответствуют [документу BT05 AT commands](https://kio4.com/arduino/imagenes/CC2540-BT05-AT-commands.pdf); это другой набор команд, чем ранее предполагавшийся HM-10. Нельзя применять профиль к произвольному модулю только по маркировке HM-10.

| Параметр | Целевое значение |
|---|---|
| UART | 9600 бод, 8N1; скорость самого модуля не переписывается |
| Команды | CR/LF в конце |
| ROLE | 0, peripheral/slave |
| Имя | CLM- и 6 HEX-цифр трёхбайтового имени MCU |
| Service UUID | FFE0 |
| Characteristic UUID | FFE1 |

Текущее имя MCU 000000 даёт **CLM-000000**. `CONFIG SET DEVICE_NAME A01` → `SAVE` → перезапуск MCU даст **CLM-413031**. Применение имени Bluetooth происходит при запуске, а не посреди соединения после редактирования. Уникальность назначает пользователь/приложение; 000000 остаётся неназначенным именем.

Роль, имя и UUID прочитаны обратно на подключённой плате. Свойства GATT write/notify и полное соединение с телефоном ещё не проверены по радио. PIN, параметры аутентификации, мощность и неизвестные функции прошивки не изменялись. Команды PWRM/IMME из HELP на этом модуле вернули ERROR, поэтому в автоконфигурацию они не включены. Factory reset/RENEW не используется.

## Последовательность MCU

1. Загрузка настроек Flash и запуск опроса температуры продолжаются обычным образом. Bluetooth обслуживается независимым автоматом bt_boot.c, без ожиданий HAL_Delay.
2. Через 500 мс отправляется AT; ожидается точный OK. При молчании — одна повторная попытка, затем NO_AT_RESPONSE. Это проверка наличия по UART, не отдельный физический датчик присутствия: занятый соединением или неисправный модуль также может молчать.
3. Проверка VERSION: настройка разрешена только для реально проверенной v6.1. Неизвестная прошивка даёт UNSUPPORTED_FIRMWARE без команд записи.
4. Чтение ROLE, NAME, UUID, CHAR. Совпадающие параметры пропускаются. Отличающиеся записываются, после выдержки 700 мс выполняются синхронизирующий AT и повторное чтение. Ответ setter сам по себе не служит подтверждением: решает чтение фактического значения. Это учитывает особенность v6.1 после изменения имени.
5. Если были изменения, выполняется один AT+RESET и повторная проверка профиля после 700 мс. При несоответствии после reset — FAILED без циклической перезаписи. При отсутствии изменений ни записи параметров, ни перезапуска модуля нет.
6. READY означает подтверждённые роль, имя, UUID. После завершения любого исхода UART6 принимает бинарный протокол телефона. Общая длительность автомата ограничена 6,5 с; молчащий модуль обычно завершается примерно за 1,2 с. Ожидания выполняются параллельно с опросом датчиков и арбитром AUTO.

Если в процессе запуска приходит 00 — начало бинарного кадра телефона, автомат прекращает AT-настройку со статусом DATA_ALREADY_ACTIVE и передаёт кадр обычному парсеру. Это позволяет продолжить существующее BLE-соединение после сброса одного MCU. Подтверждение профиля в этом случае откладывается до следующего запуска без активного обмена.

## Диагностика

В консоли появляется `BT BOOT state=READY present_by_at=1 writes=0 desired_name=CLM-000000`. Поле writes — количество отправленных команд изменения параметров модуля в этом запуске. `BT STATUS` показывает итог и фазу; FAILED дополняется последним ответом. До завершения старта ручные AT-команды возвращают BT_STARTUP_IN_PROGRESS.

Доступны BT VERSION и BT QUERY ROLE/NAME/UUID/CHAR/BAUD/LADDR. Они читают параметры модуля и временно приостанавливают обычный приём UART6. BT AT/ATLF остаются диагностикой скорости, BT HELP выдаёт справочник модуля и является локальным обслуживанием с ожиданием до 3,5 с; в автоматическом запуске HELP не вызывается. Не запускать ручные AT-проверки во время соединения телефона.

## Проверка

- На плате проверены применение временного имени A01, READY с writes=1, чтение CLM-413031 и повторный старт с writes=0.
- Затем восстановлено исходное имя MCU 000000. Модуль автоматически изменил имя обратно на CLM-000000; повторный запуск снова дал READY и writes=0. ROLE=0, UUID=FFE0, CHAR=FFE1 прочитаны напрямую.
- BT_BOOT_SELFTEST проверяет молчащий модуль, неизвестную прошивку без записей, смену всех четырёх параметров, отсутствие лишних записей, потерю ACK, провал чтения после записи, ошибку передачи, начало уже активного бинарного обмена, переполнение ответа и wrap времени. Эти случаи отказа проверены моделью; физическое отключение модуля в этом прогоне не выполнялось.
- Все SELFTEST/AUTO_SELFTEST/SETTINGS_SELFTEST/TREND_SELFTEST/PHONE_SELFTEST/BT_BOOT_SELFTEST прошли. Регрессия бинарных команд с независимым клиентом также выполнена.

Финально: AUTO, PHONE TEST OFF, STREAM ON, Flash VALID и ram_matches=1, COM3 освобождён, релейные GPIO заблокированы. Файлы сборки и логи — bluetooth-boot-release в копии результатов. Диагностическая F767-сборка всё ещё превышает лимит Flash F030; отдельная конечная сборка остаётся обязательной.
