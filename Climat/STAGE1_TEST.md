# Этап 1 — два DS18B20 и отладочная консоль

**Обновление аппаратного запуска:** прошивка записана и верифицирована. Исправлена разблокировка DWT; подтверждены 42 секундных отчёта без перезапуска, но DQ остаётся LOW и температуры пока не получены. Актуальный размер BIN 14416 байт. Подробности — HARDWARE_TEST.md; сведения ниже о невыполненной прошивке относятся к исходной версии этого этапа.

Реализован стенд чтения температуры в существующем проекте Climat. Это не прошивка регулирования: релейный арбитр, автоматическое резервирование для управления, Flash SAVE и бинарный протокол здесь не запускаются. Исполнительные нагрузки на этом этапе должны быть отключены; уровни релейных GPIO остаются стартовыми LOW, полярность ключей пока не подтверждена.

## Подключение и запуск

1. При отключённом питании соединить DQ обоих DS18B20 с PF15 / D2 / CN10-12. Внешняя подтяжка DQ к 3,3 В — стартовый номинал 4,7 кОм. Оба VDD на 3,3 В, оба GND на общую землю. Учитывать распиновку именно своего корпуса/готового датчика. Паразитное питание не поддерживается.
2. Подключить USB к ST-LINK. Открыть **STLink Virtual COM Port** в терминале: **115200, 8 бит, parity None, 1 stop bit, flow control None**. Это USART3 PD8/PD9, не окно GDB и не SWV ITM. HM-10 для этого теста не нужен.
3. Загрузить `Release/climat_test.elf` или `Release/climat_test.bin` через ST-LINK. Для BIN стартовый адрес 0x08000000. Во время выполнения задачи плата не прошивалась.
4. Открыть терминал до reset, затем нажать RESET. Появится заголовок `CLIMAT STAGE1`, после него результаты примерно раз в секунду. Если заголовок повторяется каждые несколько секунд, устройство перезапускается — это неисправность, а не нормальный режим теста.

## Что реализовано

- Поиск 64-битных ROM с проверкой CRC8, семейство 0x28. Два слота S1/S2 запоминают найденные ROM до reset; отключение не перенумеровывает второй датчик. Это ещё не утверждённые роли основной/резервный.
- Поиск повторяется каждые 5 с для обнаружения подключённых после старта датчиков. Замена уже известного датчика другим ROM требует reset; новый ROM не подменяет молча старую привязку. При более двух датчиках или достижении предела поиска выводится `extra_or_limit=1`; обрабатываются первые два назначенных ROM. Максимум восемь ветвей поиска за проход ограничивает время при шуме/лишних устройствах.
- Общий запуск Convert T и отдельное чтение каждого scratchpad через Match ROM. Период запуска 1 с; ожидание конверсии неблокирующее, первая проверка через 760 мс после команды, тайм-аут 850 мс. 1-Wire слоты и транзакции синхронные, короткие и ограниченные; поиск не является полностью асинхронным автоматом.
- CRC scratchpad, проверка структуры/диапазона −55…+125 °C, учёт 9/10/11/12-битного разрешения без изменения EEPROM датчиков. Повреждённое или отсутствующее измерение выводится `NA`, а не прошлой температурой.
- Температура хранится в 1/16 °C, печатается с четырьмя знаками после точки без float. 30-секундная история отдельно по каждому датчику; скорость по разности крайних значений и реальному времени, прогноз `T + dT/dt × 30 с`. Это простой диагностический расчёт без фильтра, не утверждённый алгоритм регулирования. После ошибки история очищается; во время накопления выводится `WARMUP`.
- Watchdog обслуживается после возврата из опроса/печати и при продвижении системного времени. Отсутствие датчиков — штатная диагностическая ошибка, не повод для reset. Зависание опроса/часов приводит к прекращению обслуживания. При остановке на breakpoint watchdog может сбросить плату.

Пример формата, **не реальные измерения**:

```text
t=1900 ms scan=OK extra_or_limit=0
S1 ROM=28... T=21.8125 C status=OK errors=0 dT=WARMUP C/min T+30s=NA C
S2 ROM=28... T=21.6250 C status=OK errors=0 dT=WARMUP C/min T+30s=NA C
```

ROM в реальном выводе содержит 16 hex-символов. `errors` — суммарное число неудачных циклов слота с момента старта, не счётчик подряд для будущего резервирования. `scan` описывает последний поиск, а `status` — текущий результат каждого датчика.

## Сообщения

| Сообщение | Значение / проверка |
|---|---|
| OK | Измерение прошло проверки |
| OK_85_CHECK_POWER | Ровно +85 °C: допустимая температура, но также значение при включении DS18B20; проверить питание, если повторяется неожиданно |
| NOT_FOUND / UNASSIGNED | Слот ещё не получил ROM; проверить проводку, дождаться повторного поиска |
| NO_PRESENCE | На reset нет присутствия устройства |
| BUS_LOW | DQ удерживается в нуле до/после reset; проверить замыкание и подтяжку |
| SCRATCH_CRC | Отсутствующий адресованный датчик либо повреждение чтения; второй датчик продолжает опрашиваться |
| INVALID_DATA | Неверная структура scratchpad или температура вне диапазона |
| PARASITE_UNSUPPORTED | Read Power Supply обнаружил паразитное питание либо неисправность линии; этот стенд требует отдельный VDD |
| CONVERSION_TIMEOUT | Шина не подтвердила завершение преобразования в пределах 850 мс |
| ROM_CRC / SEARCH_ERROR | Ошибка поиска ROM; проверить линию/питание |
| OTHER_FAMILY | На шине обнаружено устройство другого семейства |

## Проверка на столе

- Старт без датчиков: ошибки раз в секунду, MCU не перезапускается.
- Один, затем два датчика: разные ROM, корректные температуры; осторожное нагревание одного меняет его показания.
- Отключить DQ одного: у его слота ошибка/NA; второй продолжает давать измерения. Вернуть тот же датчик: прежний ROM и восстановление температуры, производная снова прогревается.
- Отключить оба: диагностические ошибки без цикла reset. Реле не управляются.
- Дождаться >30 с непрерывных данных: появляется dT и прогноз. При стабильной температуре dT около нуля.
- При доступном логическом анализаторе проверить DQ: reset low ≥480 мкс, чтение в пределах 15 мкс от начала слота, слоты около 70 мкс, открытый сток и время подъёма линии. Реальные тайминги ещё не измерены.

## Файлы и проверки

`temperature_probe.c/.h` — переносимая логика/CRC/ROM/температуры. `sensor_stage1.c/.h` — адаптер F767: GPIO, DWT-микросекунды, USART3 и watchdog. Вызовы в main.c помещены в USER CODE, чтобы сохранить их при генерации. Адаптер повторно задаёт open-drain при старте; .ioc также содержит исправленный GPIO_ModeDefaultOutputPP.

Debug: text=21472, data=120, bss=1872; Release: text=14168, data=120, bss=1872. Сумма Flash-секций Release = **14288 байт**; файл BIN — **14296 байт** с межсекционным выравниванием. Размер bss из size включает резерв стека и выравнивание; максимальный стек не измерялся. Это F7 HAL-стенд, а не подтверждение размера полной F030-прошивки.

Обе сборки завершились без ошибок и предупреждений. Общий модуль дополнительно скомпилирован для Cortex-M0 с -Os -Wall -Wextra -Werror. В `tests/test_temperature_probe.c` подготовлены проверки CRC, знака температуры, разрешения, границ, ошибочных данных, истории, переполнения времени и тайм-аутов. Тестовый исходник компилируется, но **исполнение тестов не проводилось**: доступного host C compiler/ARM simulator не найдено. Аппаратные проверки выше ещё предстоят.

Основание таймингов и команд: [официальный DS18B20 Rev 6](https://www.analog.com/media/en/technical-documentation/data-sheets/DS18B20.pdf). Настройки датчиков в EEPROM и Flash MCU не записываются.
