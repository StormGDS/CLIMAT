# Автоподбор UART Bluetooth — 02.11.2026

Реализовано в ветке dev/f030-no-service-console для F030 и F767.

При каждом запуске MCU:
1. Первоначальная скорость — 9600 бод, 8N1; ожидание питания модуля 500 мс.
2. Проверка точного ответа OK на AT с CR/LF; при молчании одна повторная попытка.
3. Если ответа нет, MCU переключает собственный UART последовательно на
   19200, 38400, 57600, 115200, 4800, 2400, 1200 бод. Перед новой проверкой
   очищаются ошибки и приём, затем выдерживается 50 мс.
4. VERSION используется только как необязательный диагностический запрос.
   Любая строка версии, ERROR или отсутствие ответа допускаются. MCU сначала
   читает все четыре параметра ROLE/NAME/UUID/CHAR. Совместимый диалект:
   +ROLE=0 или 1, непустой +NAME= (до 32 символов), +UUID= и +CHAR=
   с четырьмя HEX-цифрами. Только после успешного чтения всего набора разрешены
   записи отличающихся параметров, с последующим чтением результата.
5. При полном отсутствии AT-ответов UART MCU возвращается на 9600; статус NO_AT.
   Ошибка переключения UART даёт FAILED. Неподдерживаемый набор команд или
   некорректный формат ответов на предварительной проверке дают
   UNSUPPORTED_AT_PROFILE без команд записи. Найденная скорость остаётся в RAM.

Общий предел автомата с автоподбором — 13 с. Без callback переключения
сохранён прежний режим с одной скоростью и пределом 6,5 с.
Ожидания выполняются автоматом в основном цикле вместе с измерениями и арбитром.
Передача UART имеет ограниченный тайм-аут, рассчитанный по длине и скорости.

Скорость самого BLE-модуля не переписывается: команды AT+BAUD не отправляются.
Найденная скорость MCU не записывается во Flash; при следующем старте поиск
выполняется заново. Протокол v3, настройки v5, привязки S1/S2, PA1..PA4 active HIGH
и страница CONFIG 0x08003C00..0x08003FFF остаются прежними. PA5 не используется.
Текстовая сервисная консоль в F030 по-прежнему исключена.

Ограничения: модуль должен отвечать на AT с CR/LF в текущем режиме. Другие диалекты
AT, чётность и число стоповых битов не определяются. Если модуль уже подключён
к телефону и не принимает AT, найти нестандартную скорость таким способом
невозможно. Для замены модуль следует запускать без активного BLE-соединения.
Существующий бинарный обмен на исходных 9600 прекращает AT-настройку;
нулевые байты на других скоростях во время поиска не считаются подтверждением
активного соединения. Отсутствие Bluetooth не останавливает терморегулятор.

Изменения кода:
- bt_boot.h/c: callback bt_boot_set_uart, таблица скоростей, состояние UART_WAIT,
  текущая baud и обработка шума в пробном режиме.
- targets/stm32f030f4/board.c: переключение USART1, очистка RX/ошибок,
  регистрация callback, расчёт тайм-аута передачи.
- sensor_stage1.c: соответствующий адаптер USART6 для F767.
- bt_boot_selftest.c: проверка всех восьми скоростей, отсутствующего модуля,
  шума, разных VERSION, ERROR/молчания VERSION и несовместимого набора команд, ошибки настройки UART, потерянного ACK,
  повторной проверки после reset модуля, wrap таймера и общего дедлайна.

Проверки:
- F030 сборка/verify PASS: Flash 11672/15360 Б, свободно 3688 Б;
  RAM с резервом стека 2048 Б: 3048/4096 Б, свободно 1048 Б.
- Последняя страница CONFIG исключена из BIN; RAM Flash writer и векторы PASS.
- F767 сборка PASS; текущий размер — build/f767/build-report.json.
- Обычный, compact и no-console+compact прогоны: 16/16 каждый, всего 48 PASS.
- Связанный драйвер реле F030: 256/256 переходов PASS в Unicorn.
- git diff --check PASS.

Сборки и результаты находятся в targets/stm32f030f4/build, build/f767,
build/tests, build/tests-compact, build/tests-no-console.
Проверки выполнялись компилятором и эмулятором. На физическом модуле Bluetooth
перебор скоростей ещё не проверялся; контроллер этой версией не прошивался.
