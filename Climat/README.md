## Сборка и тесты

Артефакты build/f767. Сохраняется исходный CubeIDE-проект climat_test.ioc/.cproject;

Артефакты targets/stm32f030f4/build. Физические реле F030 LOCKED.

## Обновление прежнего устройства

Flash v1-v3 читается и преобразуется в RAM: старые on/off → Ton/H, имя и параметры
сохраняются, target отбрасывается. SAVE записывает v5. Поскольку старые версии не
хранили ROM, обе роли после миграции пустые и должны быть явно назначены.
Поиск не назначает датчики автоматически; до назначения управление получает
недостоверные датчики и после первого результата аварийную маску K3 ON.

В текстовой консоли: SENSORS → скопировать FOUND ROM, затем
`SENSOR BIND 1 ROMHEX16`, `SENSOR BIND 2 ROMHEX16`, `SAVE`.
Нельзя назначать один ROM двум ролям. После reset привязки сохраняются.

Пример температурного профиля: `AUTO SET 176 8 168 8 400 16 560 16 0`.
Последнее число — скорость в 0,001 °C/мин: например 200 означает 0,200 °C/мин.
Ноль — досрочный K2 не настроен/отключён. Нужный рабочий порог выбирает пользователь.
FAIL_COUNT и RECOVER_COUNT также нужно назначить перед вводом резервирования в работу.
Все изменения RAM сохраняются только по SAVE.

Телефон должен поддерживать протокол v3: v1/v2 получают VERSION, длины/смысл полей изменены.
Android-проекта в архиве нет; HTML остался демонстрацией v2 без BLE и не обновлялся этой задачей.
Новая прошивка в этой работе не загружалась в плату; аппаратные проверки ещё нужны.

Обновление 31.10.2026: R/Hrate и MIN_ON двух групп передаются через v3 SET_CONFIG.
Точные поля/границы — PHONE_PROTOCOL_V3.md, android_config_manifest_v3.json.
R=Hrate=0 и MIN_ON=30/60 — совместимые значения миграции. Запрет роста перекрывает
температурную защёлку K2, выключение ждёт MIN_ON и зависит от текущего запрета.
CONFIG GET показывает новые значения; старый AUTO SET сохраняет R/Hrate.
Android и HTML в этой задаче не изменялись. Отчёт: TEST_REPORT_2026-10-31.md.
